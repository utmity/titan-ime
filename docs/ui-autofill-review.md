# 入力UI・自動入力レビュー（2026-10-30）

**ユーザー承認済み範囲：候補バー・メニュー・設定の整理。** 最大3行の展開候補一覧は後回し。
以下は調査時の構成と提案、および実装範囲の記録。既存キー割り当ては変更しない。

## 変更前の構成と課題

| 対象 | 現状 | 課題 |
|---|---|---|
| 基本バー | 白背景、横スクロール、最低48dp、下部に最低32dpのナビゲーション余白 | 余白は過去の端末クリッピング対策。単純削除不可 |
| 変換候補 | 18sp、黒文字、選択は●。状態・読みに戻す・前/次文節が候補より先に並ぶ | 操作ラベルで先頭候補が押し出される。候補だけを一覧する展開UIがない |
| 英語バー | …と英語表示 | 通常欄のアプリ表示要求時のみ表示。ホーム常駐へ戻してはいけない |
| …メニュー | 縦並び。履歴・文字変換・音声・自動入力・サービス設定・IME切替・Undo/Redo・設定 | 項目が増えた。主操作と設定が混在 |
| 履歴 | 4件単位、検索、選択、ピン/削除/全削除 | 操作説明と項目が同じ視覚階層。長文は100文字で切る |
| 文字変換 | 9種類を縦並び、Fn+J/K、Enter | パネルが長い。Ctrl等まで消費していた点は今回修正 |
| 音声 | 状態文、再開始、キャンセル、外部送信の説明 | 状態と注意文の優先度が不明瞭。1回開始の動作は維持 |
| 設定 | 18sp見出しと全RadioGroupを1つのScrollViewに縦積み | 日常設定・詳細説明・データ削除が長いページに混在 |

多くのラベル余白はpx指定で、バーの最低高さはdp指定。密度変更時の一貫性と
実際のタップ領域を次のUI実装で揃える。現在のコントラスト自体を不良と断定せず、
選択状態・主副情報の区別を改善する。入力先本文の色は変更しない。

## 提案A：候補優先のコンパクトな構成

通常は48dpの1段バー。ナビゲーション領域は別計算で、現在の端末対策を維持して
測定する。文字18sp、白/淡い灰色、本文#202124、補助#5F6368を候補値とする。
選択候補は薄灰背景と太字で区別し、色だけに依存しない。

```text
通常・変換中（基本48dp、方向ボタンなし）
┌────┬─────────────────────────┬────┐
│ 日 │ 日本語   日本後   にほんご … │ …  │
└────┴─────────────────────────┴────┘
    ↑状態     ↑候補が先、横スクロール    ↑固定

候補一覧（ユーザーが展開したときだけ、最大3行×48dp）
┌─────────────────────────────────┐
│ 日本語      日本後      にほんご    │
│ その他の候補 …                    │
│ 読みに戻す                 閉じる  │
└─────────────────────────────────┘

…メニュー（案：2列、タップ領域48dp以上）
┌────────────────┬────────────────┐
│ クリップボード履歴 │ 文字変換        │
│ 音声入力         │ 自動入力        │
│ Undo            │ Redo            │
│ 入力方法切替      │ Titan設定       │
└────────────────┴────────────────┘
```

「前/次文節」の表示は基本バーから外し、既存Fn操作と操作説明へ集約する案。
「読みに戻す」は候補一覧に残す。候補展開の新しい物理ショートカットは今回決めず、
まず既存操作のSpace/Enter/Fnを維持する。メニューの自動入力サービス設定は
Titan設定内へ集約する案。パスワード欄は自動入力・IME切替・設定のみを表示する。

履歴/文字変換は見出し＋スクロール項目＋閉じるを共通化し、入力欄を残す高さ上限を
設ける。音声は「聞き取り中／認識中／再発話が必要」を大きく、キャンセルを隣接。
自動入力のリモートビュー内の文字を読み取って独自デザインへ置き換えない。

設定トップは「入力・変換」「物理キー」「辞書・学習・履歴」「音声・自動入力」
「操作ガイド」の5分類。現在モードとIME切替を上部に残す。既存の保存キーと設定値は
そのまま使用し、データ削除は確認付きの下位画面に置く。

| 変更案 | 難易度 | 影響・検証 |
|---|---|---|
| dp余白・見出し・候補強調 | 低 | 大文字サイズ、横幅、48dpタップ領域を確認 |
| メニュー整理・設定分類 | 中 | 項目の到達性、設定保持、フォーカスを確認 |
| 固定操作と候補スクロールの分離 | 中 | 候補ID/順序維持、長い候補、拡大文字で確認 |
| 展開候補一覧・パネル高さ制限 | 中 | キー操作、候補選択、IMEウィンドウ再表示の回帰確認 |

**ユーザーは候補バー・メニュー・設定整理を選択。展開候補一覧は未承認のため未実装。**

実装：48dp基本バー内の「…」を固定し、候補を優先。選択候補を薄灰背景と太字で示す。
メニューは2列にし、「読みに戻す」と未変換の「そのまま」を配置。設定は5分類の
開閉式セクションに整理し、既存の保存キー・値を維持。白背景・淡灰ボタン・濃い文字に揃え、
ボタンの立体影を外す。IME切替は設定最上部に残す。
前/次文節の画面ボタンは削除し既存Fn操作を維持。展開候補一覧・新ショートカット・
履歴や文字変換の高さ制限は今回追加しない。

## 今回実装した小規模修正

- 自動入力の遅延inflate結果を、ウィンドウ非表示・入力変更・ビュー再作成で無効化。
  古いリモートビューが候補バーを再表示しないようにする。
- 描画完了順ではなくプロバイダーの順序で候補を挿入する。表示済みリモートビューは
  付け直さず、新しく完了したビューだけを適切な位置へ追加する。
- 全候補の描画失敗時に空のパスワード用バーを残さない。描画例外でIMEを落とさない。
- 履歴/文字変換パネルでCtrl/Alt/Meta付き操作を閉じて従来のルートへ返す。
  Ctrl+ZのDown/Upがホストに届く実機回帰テストを追加。キー配置は変更しない。

## 自動入力の対応範囲と未検証事項

Android 11/API 30以降の公開InlineSuggestions API、AndroidX V1表示仕様を使用。
リモートビュー内のタップはプロバイダー/Androidのコールバックに任せ、Titanは
パスワードを取得してcommitTextしない。候補なしは正常な結果として扱い、
入力先へautofill操作を要求するか、設定から標準のサービス選択へ進める。
ホストが要求を受理したことと、実際に入力されたことは別である。

Google Play servicesが設定されていることだけを読み取り確認した。Googleや
Bitwardenの実認証情報による入力成功は未検証。サービス切り替え・実認証情報の
入力・保管庫の変更は行っていない。模擬コールバックの成功はプロバイダーの
エンドツーエンド検証ではない。Bitwardenは対応IMEとサービス側設定が必要で、
入力先のフィールド判定やURI一致にも依存する。

### ユーザーが行う確認手順

1. 現在選択済みのプロバイダーで、自分が管理するテスト用アカウントを用意する。
   別サービスを試す場合は、ユーザー自身が切り替える。
2. 対象アプリ/サイトのユーザー名欄、次にパスワード欄をタップする。
3. 候補の有無・順序・認証要求を確認し、候補を選んで対象欄へ入るか確認する。
   ログイン送信は不要。資格情報やスクリーンショットを共有する必要はない。
4. 戻る操作、別欄への移動、再フォーカスで古い候補が残らないことを確認する。
5. 候補なしの場合はホストの自動入力操作とTitan設定の導線を確認する。
6. 報告はOS、アプリ、サービス名、候補の有無、入力成功/失敗のみで十分。
