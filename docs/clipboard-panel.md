# 現在のクリップボードと複数行履歴

履歴パネルを明示的に開いたとき、接続中の通常テキスト欄に限りAndroidの
`ClipboardManager.primaryClip` を読みます。現在の単一テキストを一覧の先頭に
「現在のクリップボード」と表示し、保存がオフでも明示的に貼り付けられます。
表示のために `capture` や保存処理を呼びません。現在のコピーと同じ保存履歴は
1項目へまとめ、ピン状態と保存分の削除操作を維持します。

- 保存されていない現在項目ではピン／保存分の削除を無効化します。
- 保存分を削除してもAndroidの現在のクリップボードは消しません。
- 履歴の全削除後も、現在のクリップボードは保存せず表示できます。
- 機密フラグ付きは内容・行数を表示せず、「機密情報（内容を非表示）」と表示。
  タップ／Enterの明示操作で原文を貼り付けます。自動収集・ピン保存はしません。
  同じ内容の旧履歴も一覧では重複排除して伏せます。表示だけで既存データは書き換えません。
- 貼り付け直前に現在項目を再取得し、内容や機密フラグが変化・取得不可になっていたら
  貼り付けず再確認を案内します。パネルを閉じる／IME画面を隠す／入力を終了すると一時データを解放します。
- URI、Intent、複数アイテムを文字列へ変換しません。`coerceToText` も使いません。
  空・未対応・取得拒否時は状況を表示し、保存履歴が有効ならそちらは利用できます。
- Androidのアクセス拒否を迂回せず、バックグラウンド監視・権限追加はありません。
  既存のコピー通知からの収集は有効な通常欄・保存オン・個人学習を禁止していない欄のみです。
  パスワード／直接入力欄の既存の履歴禁止条件は維持します。

## プレビューと原文

改行は `↵`、複数行は `[3行]` などで表示します。LF／CRLF／CRを1つの改行として
数え、途中の空行や末尾の空行も含めます。表示用文字列は最大120コードポイントを
材料に作り、残りは `…`。サロゲートペアの途中で切りません。UIは最大2行・末尾省略です。
行数は先頭側に表示するため、長文の省略でも見分けられます。

保存値・貼り付け値にはプレビューを使いません。元の改行コード、空白、タブ、末尾改行を
そのまま `InputConnection.commitText` に渡します。Mozc読み／変換候補や数字スパンは
貼り付け前に確定します。保存制限（空白のみ・1万文字超・機密情報の除外）、件数制限、
重複処理・ピン・削除の永続化形式は変更しません。

通常の文字キー入力にクリップボード取得やプレビュー生成を追加しません。
取得はパネルを開く／現在項目を貼り付ける／既存の適格なコピー通知だけです。
QWERTY・ガラケーのキー配列、方式切替、ショートカットは変更しません。

## 検証

- JVM `ClipboardPanelTest`: 単一行、LF／CRLF／CR、空行・末尾改行、長文、Unicode省略、
  原文保持、機密マスク、重複の統合、履歴未保存時の現在項目。
- Android `ClipboardPanelDeviceTest`: 生のClipData抽出、機密フラグ、URI／Intent／複数項目の除外、
  分離したテスト用保存先で原文の再読み込み・既存の保存制限・ピン・削除・件数制限。
- `ClipboardIntegrationTest`: 現在項目の先頭表示、保存オフでの複数行・長文・機密項目の
  実InputConnection貼り付け、保存されないこと。既存データとクリップボードを復元します。

CIはJVMテスト・lint・各APK／端末テストAPKビルドまでです。実機は未接続で、
Androidテストは実行していません。統合テストは既存の通常版harnessと既定ショートカットで実行します。

## T2E実機で確認すること

1. Titanがコピーを収集していない間にコピー→通常テキスト欄で履歴を開き、先頭から貼り付け。
   保存オン／オフ双方で、開く・閉じるだけでは履歴に追加されないこと。
2. 保存履歴と同じ現在内容をコピーし、1項目の表示・ピン・保存分削除・全削除を確認。
3. LF／CRLF、空行、先頭末尾空白、長文、末尾改行で行数・↵・2行の高さ・省略を確認。
   貼り付け結果は全文を比較すること。
4. 機密フラグ付き内容は画面・読み上げとも本文を伏せ、保存されないこと。
   パネル表示後にコピー内容が変わった場合も、別内容を意図せず貼り付けないこと。
5. 画像・URI・空・OS側取得拒否、パスワード／個人学習禁止欄の既存制限を確認。
6. QWERTY、かな変換候補、全角数字編集中に貼り付け、未確定値と貼り付け文が両方残ること。
7. Termux等は入力接続の種類によって既存の直接入力欄制限があります。その制限は変更していません。
   利用可能な接続で改行・空白・制御文字を含む原文がIMEで加工されないことと、アプリ側の解釈を分けて確認。
